# ADR-0125：插槽转发（slots）——出口查找链的显式白名身上溯

- **状态**：Accepted（grill-with-docs，三轮收敛；终裁修订——命名 `slots` + 并存降级）
- **日期**：2026-10-21
- **关联**：[ADR-0056](0056-x-slot.md)（x-slot——出口/内容/查找链基础机制）、[ADR-0107](0107-slots-registry-and-dynamic-outlets.md)（slot 注册表与动态出口、组件路径 skipValidation、同段 N 出口独立编译）、[ADR-0108](0108-x-slot-bind-caller-bindings.md)（传递绑定——转发段照常承接）、[ADR-0084](0084-x-super-slot-fallback.md)（x-super——转发段内 fallback 展开语义不变）、[ADR-0053](0053-component-data-boundary.md)（组件数据封闭边界——转发段求值基准）、[ADR-0124](0124-overlay-content-component.md)（决策 11 消费侧 slot 上行转发——家族是本机制的**客户**：收集裁决家族专用，查找步复用本文白名身上溯，见其被否决方案「决策 11 v1 的家族专用查找」条）

## 背景

包装组件场景：b 的模板内部消费 a（`<div x-component:a>`），需要把 a 的出口暴露给 b 的消费者——b 的消费者提供 `x-slot:名` 段，应能落进 a 的出口。今日不可能，三道墙：

1. **出口查找首持有者即停**（[x-slot.ts](../../src/directives/x-slot.ts)）：内容 map 沿 parent 链找到第一个持有 `slotContents` 的 scope 后，无本名段 → fallback，不再上溯（注释明写「防穿透到外层组件」）；
2. **深嵌套标记剥除**（ADR-0056 决策九）：内容段内部的 `x-slot:*` 一律 warn + 剥属性——「b 在提供给 a 的内容里再写出口标记」的 Vue `<slot name>` 式桥接今天不可行；
3. 无任何转发通道。ADR-0124 决策 11 为覆盖物家族做过一次**上行**转发（消费者段直达 overlay chrome 出口），但那是家族专用机制，不覆盖通用的包装组件**下行**场景。

用户初始提案：`x-component-options` 增加 `replySlots` 参数声明转发清单，默认不转发；grilling 中追加重命名需求与 `true` 通配需求。

时机可行性事实：b 的内容收集发生在 b 的 `_instantiate`（先于其模板子树编译），a 在 b 模板内实例化时 b 的内容集已就绪；组件路径全量收集不校验出口清单（ADR-0107 skipValidation），闲置段可安全被转发通道读取。

## 决策

### 1. 语义模型：查找链白名身上溯（否决收集期复制与模板桥接）

转发**不是收集期动作，是出口查找链上的一步**：出口 miss 于本持有者内容集时，若本组件实例声明了转发且该出口名可翻译（显式映射或 `*` 通配），按映射翻译名字后继续上溯到下一个持有者查找。实现落点：转发映射 stash 于被消费组件的实例 scope（持有者）上，`SlotDirective` 查找循环在持有者带转发声明时按声明翻译续走，其余路径零改动。

转发命中段的求值基准 = 该段**原生持有者**的 caller basis——与上层组件自身出口消费同一段**逐位一致**（同一 holder、同一 slotCallerScope，[compiler.ts](../../src/engine/compile/compiler.ts) 既有 `holder.slotCallerScope ?? holder` 链路）：作用域形参、传递绑定（ADR-0108）、fallback、x-super（ADR-0084）、多出口独立编译（ADR-0107 决策 4）全部免费复用。

否决的替代模型：

- **收集期复制**（a 实例化时把 b 的内容集段按映射复制进 a 自己的集）：求值基准错位——内容会以内层持有者基准编译，b 模板局部变量遮蔽消费者变量；同一 `SlotContent` 双持有者生命周期耦合；
- **模板内桥接标记**（Vue `<slot name>` 式，如 `<x-passthrough name>`）：新指令 + 深嵌套标记放行 + 特殊解析规则三重成本，逐槽一行样板，且与 ADR-0056 决策九（深嵌套标记剥除）正面冲突；
- **内容侧标记路线**（在内容段上写 `x-slots.forward` 之类标记、声明「此段可被下级出口取走」）：与覆盖物内容归属容器 `x-slots`（ADR-0124）撞词根，且容器级内容（裸子节点默认段）无单元素语义落点、只能引入空载体元素——否决。

### 2. 声明通道与命名：`x-component-options.slots`

声明写在**包装组件模板内、消费内层组件的元素上**（`<div x-component:a x-component-options.slots="...">`）：

- 不在 x-define 侧——模板含多个内层组件时归属歧义；
- 不在消费者侧——消费者不应知道包装组件内部用了 a（封装边界）；
- 通道 = `x-component-options` 选项通道成员（与 props / open / dataContext 同通道惯例）；选项键名 **`slots`**（全小写——HTML 属性名 = 选项名，无 kebab 归一）：成员属性形态 `x-component-options.slots="…"`、整包形态 `x-component-options="{slots:…}"`；
- **修饰符开关形态**：`x-component:名.slots`（布尔型选项的 modifier 开关惯例，≡ `slots=true`）——修饰符匹配大小写不敏感（HTML 属性名被 DOM 小写化，`x-for` `.paging` 先例）；显式选项值在场时修饰符被压制（ADR-0007 显式优先，含显式 `false` 关闭）；
- **命名演变**：用户初始提案 `replySlots` 否决——「reply」方向感反，内容流向是自消费者**下行**入内层，内层没有在「回复」谁；v1 定名 `forwardSlots`（camelCase，HTML 属性须 kebab 书写 `forward-slots` 经 kebabToCamel 归一）；**终裁 `slots`**（用户裁决：更简短；kebab 归一成本随全小写消失）。`slots` 与既有词根近邻的区分由文档消歧承担：**`x-slot`** = 出口/内容标记指令、**`x-slots`** = 覆盖物内容归属容器（ADR-0124）、**`slots`** = 转发选项——三者拼写相近但词性与落点各异；
- v1 文本曾称「ADR-0124 已用 `forwardedSlots` 命名上行转发」——**不实**：ADR-0124 决策 11 名为「消费侧 slot 上行转发」，无独立选项键名，其查找步直接复用本机制（家族是客户非兄弟机制）。

### 3. 值语法：静态字符串清单 + 冒号映射 + `*` 通配

```
x-component-options.slots="footer, header:card-header"
x-component-options.slots="*"
x-component-options.slots="*, header:card-header"
```

- **逗号清单**；裸名 = 同名直通；
- **`出口名:对外名`** = 重导出（ES 解构 rename 惯例 original:alias）：`footer:cardHeader` 读作「内层 a 的 footer 出口，对外重导出为 cardHeader」——消费者写 `x-slot:cardHeader` 落进 footer 出口；重命名同时化解跨层重名冲突（用户需求）；
- **`*`** = 通配转发：**查找侧原名上溯**，作用域为运行时动态集合——b 的内容集里实际有什么段就能命中什么，天然覆盖动态出口（ADR-0107）与闲置段（skipValidation 收集进 map 但无静态出口的段）；与常见 glob/通配符直觉一致（用户裁决，初版曾采纳 `true` 后复改回 `*`）；
- **布尔 `true` 快捷方式**（用户后续裁决）：整包 `{slots: true}`、成员属性字符串形态 `"true"`、修饰符 `.slots` 三种书写均 ≡ `*` 全部转发——快捷方式是**整值**层面的布尔开关，列表内的 `true` token 仍不认（列表通配语义恒 `*`）；显式值（清单或显式 `false`）在场时压制修饰符开关（ADR-0007 显式优先）；
- **混写合法，显式映射项优先于通配**：`*, header:cardHeader` 时 header 出口 miss 译作 `cardHeader` 上溯，其余名字原名上溯；
- **静态字符串编译期一次解析，不响应式**（对齐 ADR-0107 决策三出口名静态绑定先例：转发清单是名字集合的静态契约，与出口名同性质）；语法非法项（`a:b:c`、空名、垃圾项）**逐项 warn + 忽略**不拖累整清单；非字符串/其他形态值 warn + 忽略。

### 4. 查找语义细节

- **default 出口可转发**（消费者裸子节点段可转发进内层默认出口）——不沿用 ADR-0124 决策 11 的 default/body 永不转发三分：那是 overlay body 出口被 shell 直通占用的家族特有约束，通用机制无此问题；
- **每级持有者各自翻译、逐级接力**：c→b→a 链（c 消费 b、b 消费 a，各级模板内各写各的声明），a 的出口 miss → 按声明在 `x-component:a` 上的映射翻译 → b 的内容集；miss → 按声明在 `x-component:b` 上的映射翻译 → c 的内容集；每级声明只管「本级出口名 → 上溯名」一跳；最终 miss → 出口自身 fallback（组件作用域求值）；
- **转发段多处渲染合法**：同名出口多级并存时各自独立渲染该段——ADR-0107 决策 4「同段 N 出口独立编译」语义的自然推广；「最近优先/消费即转移」否决——出口编译是文档序，转移标记的生效顺序不确定（时序地雷），不可实现。

### 5. warn 纪律

- **清单模式**：转发名 ∩ 声明方自身 `def.slots` 非空 → 逐名 warn（该名段将同时被自身出口与转发下游消费——双渲染 footgun 提示，编译期一次、列出名字、不阻断）；
- **`*` 模式**：声明方 `def.slots` ∩ 相邻下一级组件 `def.slots` 非空 → warn 一次列出交集；不深扫多级、动态出口场景不追求精确（与 ADR-0107 skipValidation 同款容错哲学）；
- default 出口转发同纪律。

### 6. 并存降级与多级回退（终裁修订，Design B）

v1 语义「持有者直供命中优先——命中即 break，转发只服务 miss 名」在并存场景名实不符：包装层对 N 声明了转发，消费者却永远无法覆盖包装层自己直供的 N 段——转发声明形同虚设。终裁修订：

- **并存降级**：持有者对名字 N 声明转发**且**自身内容集有 N 直供段 → 直供段**降级为回退候选**，查找按译名继续上溯，可被外层消费者段覆盖；
- **未声明名恒优先**：持有者未对 N 声明转发 → N 直供段**终局命中即胜**（「首持有者即停」不变式对未声明名字 100% 保留）；
- **多级回退 = 最外层赢**（Q3 裁决）：链上多个持有者各降级出候选时，走完链无终局命中 → **最后一个候选（最外层）兜底**；
- 链走尽无候选 → 出口自身 fallback（v1 现状不变）。

## 被否决的方案

- **`replySlots` 命名**：方向感反（内容下行非上行回复）——否决；v1 `forwardSlots` 后终裁 `slots`（更简短，用户裁决；kebab 归一成本随全小写消失，与 x-slot / x-slots 的区分由文档消歧承担——决策 2）；
- **收集期复制**（M2）：求值基准错位 + 双持有者生命周期耦合（决策 1）；
- **模板内桥接标记**（M3，Vue `<slot name>` 式）：三重机制成本 + 与深嵌套标记剥除决策冲突 + 逐槽样板（决策 1）；
- **内容侧标记路线**：与归属容器 `x-slots` 撞词根 + 容器级内容无语义落点只能空载体（决策 1）；
- **最近优先/消费即转移**：出口编译文档序导致转移标记生效顺序不确定——时序地雷（决策 4）；
- **`true` 通配 token**：初版曾采纳，后复改回 `*`（用户裁决——通配语义与常见 glob/通配符直觉一致，决策 3）；**整值布尔 `true` 快捷方式后经用户裁决重新采纳**（≡ `*`，非清单 token——列表内 `true` 仍不认），并派生 `.slots` 修饰符形态（决策 2/3）；
- **响应式转发清单**：名字集合静态契约与出口名同性质，响应式需拆旧投影重编译，场景存疑 YAGNI（决策 3）；
- **x-define 侧声明**：多内层组件归属歧义；**消费者侧声明**：破坏封装——消费者不应知道内层组件存在（决策 2）；
- **default 出口排除**：ADR-0124 三分是家族特有约束（body 直通占用），通用机制无此问题（决策 4）；
- **v1「直供段恒优先」的并存语义**：声明转发后消费者仍无法覆盖包装层直供段，转发名实不符——终裁改为并存降级（决策 6）。

## 后果

- ✅ 包装组件场景闭环：b 的消费者可填充 a 的出口，`*` 通配 + 显式重命名双形态覆盖全转发与精准转发；
- ✅ 多级组合（c→b→a）每级声明即逐级接力，`*` 在中间层即为全链贯通提供零成本通道；
- ✅ 转发段与上层组件自身出口消费同段行为逐位一致——零新求值管线；
- ✅ 并存降级使转发声明名实相符：消费者段 > 直供段（已声明名）> 直供段（未声明名）> 最外层候选 > fallback 的优先级链完整；
- ⚠️ 「首持有者即停」不变式获得**显式声明才生效**的例外——防穿透原则对未声明名字 100% 保留；
- ⚠️ **行为修订（v1 → 终裁）**：声明转发的持有者其直供段从「恒优先」变为「回退候选」——升级时依赖旧行为的包装组件需自查；
- ⚠️ 多级同名出口 = 多处渲染（warn 纪律管 + 文档标注），非「最近优先」；
- **交付**：ADR（本文）+ CONTEXT.md 词条 + 源码（`x-component-options` 解析 `slots`（清单 / 布尔 `true` 快捷方式 / `.slots` 修饰符开关）、持有者 scope 转发映射 stash、`SlotDirective` 查找循环上溯 + 并存降级候选兜底、warn 集）+ 测试（单级直通/重命名/`*` 通配/混写优先级/全转发快捷方式（布尔/字符串 true/修饰符——含大小写不敏感与显式压制）/多级接力/同名双渲染 warn/语法非法逐项忽略/default 转发/并存降级五态（消费者胜过直供、无消费者直供渲染、未声明名恒优先、多级最外层赢、重命名按译名命中））+ 文档（x-slot 与 x-component 指南「插槽转发」节含三词消歧说明）。
