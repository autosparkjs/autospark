# Spec：指令文档统一模板（五段骨架）

> 关联：校验实现 `scripts/check-doc-structure.ts`；规范落地于 `docs/zh/guide/directives/x-*.md`（26 篇，x-patch 除外）。栏目名与表格表头以本文为准，改稿前先跑校验器。

## Problem Statement

`docs/zh/guide/directives/` 下的指令文档结构各自为政：H1 格式不一（有缺中文名的）、章节顺序不同（有的无「快速入门」、有的以「标记一览」类清单开篇）、配置表格列数与表头不统一（三列「配置项 | 类型 | 说明」与四列混用）、特性小节有的带可运行演示有的是纯论述。读者每读一篇都要重新建立阅读预期；评审者无法机器判定结构合规；改稿时无据可依，锚点死链靠构建偶然暴露。

## Solution

把每篇指令文档统一为**五段骨架**，并提供机器可校验的结构规则：

```markdown
# x-{name} {中文名}

## 概述          # 一两句定位 + 最小示例 / 适用范围提示
## 快速入门      # <demo> + 引导文字（最短可跑路径）
## 指南
### 指令值      # 固定首节：值语义与形态总览，多形态用 #### 子标题
### {特性}…     # 每特性一节 = 引导文字 + <demo>（纯论述型例外须记录在案）
## 配置选项      # 可省略；存在则 H2 正文置顶统一四列表格
## 注意事项      # 必有
```

校验器 `bun scripts/check-doc-structure.ts`（无参=全量，x-patch 除外；有参=指定文件）对骨架报 **ERROR 并 exit 1**，对 demo 缺口等报 **WARN 不阻断**（WARN 文案即「请人工确认例外」）。

## User Stories

1. 作为读者，打开任意指令文档都能按「概述 → 快速入门 → 指南（先指令值后特性）→ 配置选项 → 注意事项」的固定顺序找到信息，不因篇而异。
2. 作为文档作者，新增指令页有明确模板可抄，跑一条命令即可知道结构是否合规，不必人工比对既有篇章。
3. 作为文档作者，需要某特性没有现成 demo 时，知道「纯论述型例外」的记录口径，而不是随手空着。
4. 作为评审者，结构问题由校验器以 ERROR 阻断，内容与例外合理性由人审——两类关注点分离。
5. 作为维护者，改动标题后能有一条「全站入链 grep」的收尾动作可依，不依赖构建偶然暴露死链。
6. 作为维护者，改稿跑校验 + 构建 + demo 引用存在性检查三步即可确认未破坏结构。

## Implementation Decisions

1. **H1 格式**：唯一、置于文首、`# x-{name} {中文名}`（允许点记号 `x-for.paging` 等修饰符形态）；**不使用 frontmatter**。
2. **H2 骨架顺序固定**：`概述 → 快速入门 → 指南 → [配置选项] → 注意事项`。`配置选项` 为唯一可省段（无任何指令选项/修饰符的指令整体省略），其余四段必有。
3. **指南首节固定 `### 指令值`**：值的语义、形态与读写方向总览；多形态用 `####` 子标题（如 x-dialog 的「状态驱动 / 表达式驱动 / 字面量 / 空值」）。该节**豁免** demo 警告（值语义常由后续特性节演示覆盖）。
4. **每特性 = 一个 `###` 小节 + 引导文字 + `<demo/>`**：demo 必须出现在该节**任何 `####` 子标题之前**（校验按「首个子标题之前的正文」判定，子标题正文不查）。纯论述型小节（机制、原理、边界）允许无 demo，但须在改稿记录中登记为**人工确认例外**。
5. **配置选项四列表格**：表头逐字 `配置项 | 默认值 | 修饰符 | 说明`，置于 `## 配置选项` **正文内（首个子标题之前）**——H2 含 H3 子节的写法不合法（表体会被判在子节名下）。方言：配置项 = 不带点的选项名，修饰符列 = 带点修饰符名（`.number`）或 `—`（无对应修饰符）；类型信息并入说明列。
6. **校验语义**（与实现一致）：先剔除代码围栏行再解析——因此**只有 `<demo` 标签计数，代码块不算 demo**；`指令值` 节豁免；警告循环遇到下一个 H2 即止（`配置选项` 内的 H3 与所有 H4 不查）。ERROR 阻断（exit 1），WARN 不阻断。
7. **内容重组原则**：复用为主、缺口补写、多余内容归位——旧章节的演示挂回对应特性节，无家可归的清单并入 `### 指令值`，重复/过期表述剪除；demo 不够时在 `docs/demos/**` 新建纯 HTML 可运行页（引用 `<demo html="相对 docs/demos 的路径">`）。
8. **锚点保持**：改标题必须同步全站入链——先 grep `](#`、`x-*.md#` 找引用方，锚变更时改引用方（不回改标题向错误锚点妥协）；入链集中的标题（如 x-model 的「字段拆分 / 字段组合 / 字段联动 / 自动注入 / select」）优先原样保留。
9. **范围**：`x-patch.md` 为废弃迁移存根，校验器 `EXCLUDE` 排除、内容不动；文件名与 `.vitepress` 侧边栏不动（结构统一不改信息架构）。

## Testing Decisions

1. `bun scripts/check-doc-structure.ts` 全量通过：**0 错误**；WARN 仅允许登记在案的纯论述型例外（改动批次内逐条核对与预期清单一致）。
2. `cd docs && bun run build` 通过：暴露相对死链（站内 md 链接）与渲染问题；engine ADR 等站外文件用 GitHub blob 绝对链接（见 `docs/zh/guide/tooltip.md` 口径）。
3. grep 校验全部 `<demo html="…">` 引用在 `docs/demos/` 下存在（demo 改名/删除不致静默失效）。
4. 逐篇抽查重灾区：章节迁移处的上下文衔接（原「上例」类指代在 demo 搬家后仍成立）与被改标题的入链。

## Out of Scope

- 指令文档的**内容正确性**重写（本文只统一结构与呈现口径；语义以 engine 源码与 ADR 为准）。
- 文件名、侧边栏、目录位置调整；孤儿页（`docs/zh/guide/x-for.md`、`docs/zh/guide/tooltip.md`）。
- `x-patch.md`（废弃存根，维持原样）。
- 英文版文档（仓库当前仅中文）。

## Further Notes

- 三批次执行（批1 10 篇 / 批2 8 篇 / 批3 8 篇）共登记纯论述型例外若干（如 x-icon「图标注册表」、x-tree「循环变量（九元组）」、x-dialog「面板边框（border）」）；例外清单随改稿评审记录走，不写入文档正文。
- 校验器刻意「警告不阻断」：demo 缺口是内容债信号，不应卡住结构合规的 CI 语义；需要阻断时再引入分级阈值。
