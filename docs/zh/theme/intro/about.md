# 关于 AutoSpark Theme

`@autospark/theme` 是一个 **CSS 变量驱动的运行时主题库**：你给它一个主题色，它在浏览器里派生出整套界面变量，并提供暗色、多彩、尺寸与作用域开关。

```js
import { themeManager } from "@autospark/theme";

themeManager.themeColor = "green"; // 预设主题色
themeManager.dark = true; // 暗色模式
```

## 核心价值

**一个主题色，整套界面变量**——不需要人工枚举 10 阶色板、不需要为暗色再写一套色值、不需要为每种模式/色彩组合准备皮肤。

主题的「分层」被固化下来：

```
主题色（seed）
  → 基础量（--x-*：色阶、字号、间距、圆角、阴影……）
  → 语义量（--auto-*：文字色、背景色、边框、主色、交互态……）
  → 组件消费（.auto-btn / .auto-card / .auto-input ……）
```

组件只消费语义量，因此换主题只动最上游一层。

## 它解决什么问题

传统做法里，「换主题」往往是三件事的合集：维护多套色板、为每种模式写一套 CSS、保证改色后没有漏改的地方。主题库把这三件事收敛为运行时的一次变量重算：

- **派生**：10 阶主色标尺由算法生成（Material 风格色板扩散），不是手写常量。
- **分层**：组件样式只引用 `--auto-*`，模式差异集中在变量层，组件层保持模式无关。
- **作用域**：主题是一等对象（`ThemeScope`），可以全局、也可以局部，还能持久化。

## 与静态 CSS 的关系

包同时提供两层，二者可以单独使用，也可以叠加：

| 层 | 内容 | 何时需要 |
| --- | --- | --- |
| **静态样式层** | reset、工具类、组件类（`.auto-btn` / `.auto-card` / `.auto-input` …） | 任何时候都需要，负责「长得好看」 |
| **运行时主题层** | 由 `ThemeManager` 注入的 CSS 变量（色阶、模式、尺寸） | 需要动态换主题时 |

只引静态层时，可以用内联的默认变量值（灰阶 + 内置默认语义色）；引入运行时后，静态层里的组件类会消费运行时注入的 `--auto-*`，随主题实时变化。

::: tip 双真值源的边界
静态层只定义灰阶（`--x-color-gray-*`）等**与主题无关**的量；主题色标尺与语义色**只由运行时注入**——同一变量不会在两层各写一份，避免层叠竞争。详见[静态主题包](./../guide/static.md)。
:::

## 与 AutoSpark 生态的关系

- **AutoSpark Engine**：负责模板渲染与交互；主题库提供它所需的外观变量。
- **AutoSpark Components**：纯 HTML 组件资产；其外观类直接消费 `--auto-*` 变量。
- 三者共用同一套变量命名与类名前缀（`--x-*` / `--auto-*` / `auto-*`），组合使用无需适配层。

## 适用场景

- 需要暗色模式 / 品牌色定制 / 密度切换的中后台系统
- 需要「页面里再放一个独立主题区域」的编辑器、预览器、文档站
- 想用一套变量把已有 CSS 组件接入主题体系的存量项目
