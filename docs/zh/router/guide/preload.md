# 预加载

::: warning 规划中
预加载特性**尚未实现**——本页描述的是类型面上的预留设计与规划语义，运行时行为会在后续版本落地。当前版本声明 `preload` 字段不会产生实际效果。
:::

## 关于

预加载（preload）指**在用户导航之前**提前加载某些路由的视图与数据——用户真正点击时内容已就绪，导航瞬时完成。这是静态文件路由架构下改善"首次点击体验"的主要手段。

类型面已预留：

- 路由项 `preload: boolean` 字段（`true` 表示在初始化时自动加载视图数据）
- `routeOptions.preload` 全局缺省配置
- 加载器选项层的 `preload` 声明（在路由实例创建时自动预载进缓存，加速后续取用）

## 指南

### 预留的声明方式

以下写法在类型上合法，语义为规划行为（当前版本无运行时效果）：

```js
const engine = new AutoSpark(host, {}, {
    routes: [
        { path: "/hot", view: "/views/hot.html", preload: true },  // 规划：初始化时预载
        { path: "/cold", view: "/views/cold.html" }
    ],
    routeOptions: {
        preload: false   // 全局缺省
    }
});
```

### 当前的替代方案

在预加载特性落地前，可用以下方式达到近似效果：

**预热网络层缓存**：直接利用数据通道的 `cache`，应用启动后手动请求一次热点路由的数据，进入路由时命中缓存：

```js
// 应用启动后预热（cache 有效期内导航免请求）
fetch("/api/hot-data").then(() => {});
```

**降低首次渲染成本**：对内容型路由使用 raw 通道（`!` 前缀视图）跳过模板编译，详见[渲染器](./renderers/html.md)；配合 `keepAlive` 让二次进入零成本复用，详见[缓存](./cache.md)。

### 设计预告

规划的预加载行为将复用既有加载管线（视图加载器与数据加载器的缓存、超时、插值语义全部一致），预计支持：

- 路由项级声明（初始化预载指定路由）
- 全局 `routeOptions.preload` 缺省
- 与 `cache` 配合决定预载后是否驻留

落地后本页将更新为完整指南。
