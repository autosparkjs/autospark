# 组件插槽

## 概述

**插槽**是组件的**内容投影**机制：组件在模板里预留若干可替换位置（**出口**），使用者实例化时向其中填入自己的内容——填了就替换，没填就显示组件写好的默认内容（**fallback**）。有了插槽，一个组件不必为「页头换不换、正文放什么、页脚留不留」各出一个变体，结构与默认行为由组件定，差异部分交给使用者填。

三方分工：

| 角色 | 写什么 | 作用 |
| --- | --- | --- |
| **组件作者**（`x-define` 内） | `x-slot` / `x-slot:名` 标记出口，出口内写默认内容 | 预留可替换位置 + 兜底样子 |
| **组件使用者**（`x-component` 宿主子级） | 裸子节点 / `<template x-slot:名>` 填入内容 | 按名投影覆盖 |
| **引擎** | 无需配置 | 编译期自动收集出口清单与内容段，实例化时投影 |

最小示例：

```html
<!-- 组件作者：两个出口 + 一段固定页脚 -->
<div x-define="card">
    <header x-slot:header>默认标题</header>
    <div x-slot>默认正文</div>
    <footer>固定页脚（无 x-slot 标记，永远不会被替换）</footer>
</div>

<!-- 使用者：按名填入 -->
<div x-component:card>
    <template x-slot:header><h1>自定义标题</h1></template>
    <p>填入默认插槽的正文……</p>
</div>
```

不填内容时两个出口显示组件内的默认文案，固定页脚照常；填了内容则按名替换，固定纹丝不动：

## 定义出口

在 `x-define` 的组件模板里，给希望被替换的元素写上 `x-slot`：

| 写法 | 含义 |
| --- | --- |
| `<div x-slot>…</div>` | **默认出口**（名 `default`），内容侧的裸子节点填到这里 |
| `<header x-slot:header>…</header>` | **命名出口**，使用者按 `header` 这个名字填入 |
| `<footer>…</footer>`（无标记） | **固定内容**，使用者无法替换 |

要点：

- **出口清单自动推断**——编译期扫描模板得出，没有（也不需要）`slots: ['header']` 之类配置；
- **标记元素保留为包裹层**（标签不拆）——出口在哪、DOM 就在哪，fallback 有宿主、CSS 好写；运行期出口元素带 `data-slot="<出口名>"` 锚点；
- 出口可位于模板**任意深度**，嵌套出口合法；
- 同名出口写多处只认第一处，其余剥除并 `warn`；
- 写在 `x-define` **根元素上无效**（不收集）；组件外的 `x-slot` 收不到任何内容，只作普通属性渲染。

## 提供内容

实例化时在 `x-component` 宿主的**直接子级**填入内容：

| 写法 | 效果 |
| --- | --- |
| 直接写子节点（`<p>正文</p>`） | 填入**默认出口**（多个裸子节点合并为一份） |
| `<template x-slot:header>…</template>` | 填入命名出口；`<template>` 自身不渲染，子节点直接展开 |
| `<div x-slot:header>…</div>` | 同样填入命名出口，但该 `<div>` 保留为包裹层 |

收集规则：

- **仅直接子级参与识别**——嵌套更深一层的 `x-slot:*` 会被 `warn` + 剥除标记，元素按普通内容处理。出口侧深、内容侧浅的**不对称是有意的**：出口是组件作者的结构声明（深度自由），内容是调用方的扁平投影（直接子级分段清晰）；
- 收集时是**克隆**，不改动原模板；同一组件多次实例化各取各的内容；
- 内容名在组件路径下没有对应出口时**静默闲置**——进 `$slots` 注册表，不渲染也不警告，任何情况下都不会插错位置（覆盖物 / 继承路径则是 `warn` + 丢弃）；
- **覆盖物路径例外**：`x-dialog` 等宿主的裸子节点（按钮标签等）**永不参与收集**，内容须显式声明，多消费者还要 `x-slots="组件名"` 容器分家，见 [x-slots](../../directives/x-slots.md)。

## 求值作用域

填入的内容与默认内容**不在同一侧求值**，这是插槽最核心的一条语义：

| 子树 | 求值作用域 | 说明 |
| --- | --- | --- |
| 使用者填入的**内容** | **调用方作用域链** | 读页面 `x-data`、全局 state，**不受组件封闭边界约束** |
| 出口内的**默认内容（fallback）** | **组件作用域** | 出口是组件模板的一部分，天然读组件 data |

嵌套组件时不串台：内容 map 沿作用域链**就近**查找——内层组件的出口只认自己收到的那份内容，找不到就显示自身 fallback，**不会向外层组件穿透**。

## 作用域插槽

出口不只是「换个位置」，还能把**组件状态传给内容侧渲染**——两侧各写一份形参声明，经共享容器注入：

```html
<div x-define="list">
    <!-- 出口侧：值 = 对象字面量，在组件作用域求值，watch 保持响应式 -->
    <li x-slot:row="{ item, index }">#{{ index }} {{ item }}</li>
</div>

<div x-component:list>
    <!-- 内容侧：解构形参，在内容作用域解出传出值 -->
    <template x-slot:row="{ item, index }">
        <b>{{ item }}</b>（{{ index }}）
    </template>
</div>
```

要点：

- 传出的是**响应式引用而非快照**——组件内改动数据，内容侧原地刷新；
- 形参容器挂内容作用域，**遮蔽**使用侧同名变量；需要外部值请换名或不声明形参；
- 形参只支持最简解构形 `{ a, b }`——不能改名、不能默认值；
- **裸子节点没有形参**（无形参通道），默认出口要形参须显式写 `x-slot="…"` 标记。

## 传递绑定

内容只能换掉出口**内部**的子树，出口**元素本身**（那个 `<header>`）的 class、属性、事件由组件写死。使用侧的 `x-slot.bind` 把一个对象**展开到出口元素**上——表达式在调用方作用域求值、响应式更新：恒赢出口静态属性（调用方赢），`class` / `style` 例外走合并（组件侧 token 保留）。

```html
<div x-component:card>
    <template x-slot:header x-slot.bind="{ class: 'big', 'data-id': id }">
        <h3>自定义标题</h3>
    </template>
</div>
<!-- 出口渲染为 <header class="base big" data-id="…"> -->
```

语义与订阅粒度同 [x-bind](../../directives/x-bind.md) 展开；形参与绑定可共存（同一标记元素），无形参时用别名 `x-slot:header.bind` 或空载体 `<template x-slot.bind>`。完整规则见 [x-slot · 传递绑定](../../directives/x-slot.md#传递绑定-x-slot-bind)。

## 动态插槽

静态出口的名字写死在属性名里，出口集合编译期即固定。要让**出口数量与名字由数据决定**（tabs：每个标签一个出口），组件侧用**带值的裸 `x-slot`** 声明动态出口，配合组件实例域的只读注册表 `$slots` 查看调用方给了哪些名字：

- 出口名在**编译期求值一次后静态绑定**，不响应式——改名 / 新增出口靠 `x-for` 重建子树；
- 对象形态 `x-slot="{ name: key, params: { index: i } }"` 里 `params` 走 watch，**保持响应式**；
- `$slots` 是框架保留键：名 → 冻结快照的只读注册表（`Object.keys($slots)` 即「调用方提供了哪些名字」），赋值被忽略并 `warn` 一次；
- **内容名恒静态**（调用方名字只能写在属性名里）——调用方静态决定「有哪些名字」，组件动态决定「渲染哪些」，内容可以为将来的出口**预置**，不能运行时临时造名。

## 叠加默认内容

提供内容默认是**整体替换** fallback。要在自定义内容里**引用**被覆盖的默认内容（前缀增强、包裹、交错排版），在内容里写 `<x-super></x-super>`——它把本段覆盖的那份 fallback 原位展开进标记内部：展开部分在**组件状态**求值，自定义内容在**使用处状态**求值，互不混淆。

<demo html="slot/super.html"/>

语义要点与边界规则见 [x-super](../../directives/x-super.md)。

## 插槽与组件继承

[组件继承](./inherit.md)（`x-define:inherit`）的覆盖走的是**同一套插槽分段规则**：子定义的直接子节点按命名段 / 默认段收集，替换父组件对应出口的 fallback——与消费侧写法完全对称。区别只在求值作用域：继承覆盖段在**合并后的组件数据域**求值（父子数据与方法全可见），消费侧内容则在调用方作用域求值。覆盖只是替换 fallback，实例化时消费方仍可再提供同名内容。

## 常见问题

- **内容没显示**：检查是否写在宿主直接子级、名字是否与出口一致（组件路径名字对不上**不警告**，只静默闲置，可先看 `$slots`）；
- **内容读不到组件内部状态**：内容在调用方作用域求值是设计使然——要组件状态请由出口侧以作用域形参传出；
- **覆盖物内容丢了**：`x-dialog` 等的裸子节点永不参与收集，见 [x-slots](../../directives/x-slots.md)；
- **别给 `$slots` 赋值**：只读注册表快照，写入被忽略并警告。
