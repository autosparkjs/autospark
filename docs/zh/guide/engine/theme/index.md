# AutoSpark Theme

::: warning 核心定位
`@autospark/theme` 不是一套「写死的主题 CSS」，而是一个**CSS 变量驱动的运行时主题库**——给一个主题色，它在浏览器里派生出整套界面变量（灰度阶梯、背景层次、文字三档、边框、阴影、交互态），并支持暗色、多彩、尺寸调节与全局 / 局部作用域。
:::

它解决的是「一套界面要同时长得对、又要在运行时换皮」这件事。设计 token 的**分层**（基础值 → 语义别名 → 组件消费）被固化在变量体系里，组件样式只消费 `--auto-*` 语义变量，因此换主题色、切暗色、调尺寸都不需要改一行组件代码。

```html
<link rel="stylesheet" href="/path/to/theme/dist/index.css" />

<script type="module">
    import { themeManager } from "@autospark/theme";

    themeManager.themeColor = "purple"; // 换主题色（预设名或任意色值）
    themeManager.dark = true; // 切暗色
    themeManager.colorized = true; // 多彩（灰阶幕布换主题色浸染）
    themeManager.radius = "large"; // 调圆角
</script>
```

## 主要特性

1. **单色派生整套变量** —— 只给一个主题色，动态生成 10 阶主色标尺（`--x-color-theme-0..9`），并派生文字三档、背景层次、边框、交互态等整套 `--auto-*` 语义变量。

2. **语义色作为梯度种子** —— `primary` / `success` / `warning` / `danger` / `info` 五色的值会展开为同系 10 阶标尺（`--x-color-{name}-0..9`）；亮色直引种子原值（视觉零变化）、暗色提亮引用浅档，深底上语义色不再「越调越暗」。

3. **暗色 / 多彩 / 无彩三态可控** —— 显示模式维度（暗色 ↔ 亮色）与色彩维度（多彩 ↔ 无彩）相互独立、可自由叠加，且支持**局部**启用：作用域元素上的 `dark` / `colorized`，或任意元素裸挂 `data-dark` / `data-colorized` / `data-light` / `data-uncolored`。

4. **全局 + 局部作用域** —— 根作用域接管整个文档，`addScope()` 可为侧边栏、预览区、WebComponent 等子树建立独立主题（独立主题色 / 独立模式 / 独立尺寸），互不干扰。

5. **四维尺寸调节** —— `size`（字号 / 行高 / 间距体系）、`radius`（圆角）、`spacing`（内外间距）、`shadow`（阴影）四维各六档，支持 `medium` 默认态与局部覆盖。

6. **样式自注入 + 自持久化** —— 主题 CSS 由运行时注入 `<style>`，不依赖构建期预生成；注入结果自动写入 localStorage 样式快照，配合 head 内的一小段阻塞脚本，**回访用户首帧前即还原主题、零闪烁**。

7. **零构建依赖的静态层** —— 同包附带一份纯 Less/CSS 静态样式层（reset / 工具类 / 组件类），与运行时主题变量叠加使用；不经运行时的消费者也可以直接引预设主题 CSS。

8. **可读性有量化兜底** —— 暗色各档按 WCAG 对比度校准（正文 ≥ 4.5:1、图形 ≥ 3:1），并随包提供对比度校准脚本，改变量后可直接跑数值回归。

9. **与 Autospark 生态同构** —— 变量命名（`--x-*` 基础量 / `--auto-*` 语义量）、组件类名（`auto-input` / `auto-btn` / `auto-card` / `auto-alert`）与 AutoSpark Engine、AutoSpark Components 保持一致，主题即「引擎组件的皮肤」。

10. **完整的类型与工具导出** —— 包内导出 `ThemeManager` / `ThemeScope` / `ThemeObserver` / 预设主题表 / 颜色解析工具 / 类型定义，类型声明随包发布，TypeScript 开箱即用。

## 产品优势

- **换皮成本最低** —— 主题色的改变不需要重新编译，也不需要扫描替换色值：改一个变量，全部消费 `--auto-*` 的组件自动跟随。
- **模式与色彩解耦** —— 暗色与多彩是两个独立维度，「暗色 + 多彩」有明确的叠加语义与映射规则，不必为每种组合写一套皮肤。
- **局部主题天然支持** —— 同一页面里可以既有一个亮色灰调主区、又有一个暗色彩调预览区，作用域机制让主题边界显式化。
- **首帧体验可控** —— 持久化 + 恢复片段把「回访闪一次默认主题」压到零闪烁；且快照**自愈**（每次注入变化全量重写），不设版本号也不会脏读。
- **可量化** —— 对比度校准脚本与主题变量同源，颜色调整有数值依据，而不是靠肉眼比对。

## 与相邻方案对比

| 维度 | AutoSpark Theme | 手写 CSS 变量 | 设计系统 token + 预生成主题 | CSS-in-JS 主题 |
| --- | --- | --- | --- | --- |
| **主题来源** | 单个主题色 → 运行时派生整套变量 | 人工枚举每个色阶值 | 构建期预生成多套主题产物 | JS 对象 → 运行时生成样式 |
| **换主题时机** | 运行时（改属性/变量即可） | 运行时（但需自己写全每套值） | 通常需重新构建 | 运行时 |
| **模式与色彩** | 暗色 / 亮色 / 多彩 / 无彩 四属性独立组合 | 需手写全部组合 | 视实现而定 | 视实现而定 |
| **局部主题** | 内置作用域（`addScope` / `data-theme-scope`） | 需自行设计选择器边界 | 少见 | 依赖组件树 Context |
| **首访 / 回访闪烁** | 首访接受 FOUC，回访零闪（快照 + 恢复片段） | 无（静态 CSS） | 无（静态 CSS） | 视实现而定 |
| **引入成本** | 一个包 + 两行初始化 | 零依赖，但维护成本高 | 构建链路改造 | 需接入 JS 样式运行时 |

**一句话定位**：手写 CSS 变量是「自己实现一套主题」，token 预生成是「构建期把主题编译出来」，CSS-in-JS 是「用 JS 表达样式」；而 `@autospark/theme` 是**运行时把主题算出来**——一个主题色进、整套变量出，模式/色彩/尺寸/作用域四个维度都在运行时切换。

## 适用场景

- **中后台系统 / 多主题产品** —— 需要暗色模式、品牌色定制、紧凑或宽松密度切换。
- **需要局部主题的页面** —— 代码预览器、文档示例区、可视化编辑器画布等「页面里再放一个独立主题区域」。
- **与 AutoSpark Engine 搭配** —— 引擎负责交互与数据，主题库负责外观变量，组件类直接复用。
- **渐进式增强** —— 已有页面只引入静态样式层也能用；需要动态换肤时再引入运行时。
