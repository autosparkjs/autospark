# 性能优化

## 关于

router 的性能模型围绕三个关键词：**少请求**（缓存与复用）、**少加工**（raw 通道）、**不阻塞**（后台展开与并发加载）。本章汇总各特性的性能语义与调优建议。

## 指南

### 缓存体系

三层缓存按需启用，详见[缓存](./cache.md)：

| 手段 | 收益 | 代价 |
| --- | --- | --- |
| `keepAlive: true` | 二次进入零渲染成本，运行态保留 | DOM 常驻占内存 |
| `cache: <毫秒>` | 有效期内零网络请求 | 数据时效性下降 |
| 出口 `mode: "tabs"` | 页签切换瞬时完成 | 全部视图常驻 |

::: tip 全局调优
`routeOptions: { cache, keepAlive, timeout }` 一处声明全站缺省，个别路由覆盖。
:::

### raw 通道

对确认无模板需求的内容页（正文、文档、营销页），视图 URL 加 `!` 前缀跳过 DOMParser 解析与模板编译，`innerHTML` 直插即完成——渲染成本近零，详见 [html 渲染器](./renderers/html.md)。

### 已加载层跳过

嵌套路由导航（`/a/b` → `/a/c`）时，父层视图与数据已成功加载过就**不再重新请求**，只加载变化的子层——嵌套层级越深收益越明显，详见[视图加载](./view-loading.md)。

### 并发加载

同一导航内，各匹配层的**数据与视图并发加载**（`Promise.allSettled`），导航总耗时 ≈ 最慢的那一路，而非各路之和。合理设置 `timeout` 避免单路拖死整次导航：

```js
routeOptions: { timeout: 8000 }
```

### 远程子表后台展开

路由表加载只等骨架就绪（`routes:loaded`），远程子表**逐层并发**后台展开，不阻塞首屏；同地址子表响应按 URL 缓存复用，一次请求多处挂载，详见[远程路由](./remote-routes.md)。

### 数据通道复用

并发复用策略 `multiplex: "share"` 让进行中的同 hash 数据加载被后续导航**直接共享**，避免重复请求打满并发：

```js
data: {
    from: "/api/heavy-report",
    cache: 300_000,        // 结果驻留 5 分钟
    multiplex: "share"     // 进行中的加载直接共享
}
```

### 下载体积

- 静态模板中未用到的路由不声明 `view`——纯容器节点（目录层）不产生任何请求
- 大体量子树用远程子表按需拆分：用户走到哪个模块，哪个模块的表才被拉取
- 图片等二进制资产走 [image 渲染器](./renderers/image.md)时注意：router 仍会 fetch 校验存在性，超大图建议配合 CDN 缩略参数

### 反模式清单

- **把 `{path}` 当视图 hash 默认理解**——参数化路由不同参数坍缩为同一复用键，表现为"切换不刷新"；保持默认 `{url}`，除非有意跨参数共享实例
- **对动态内容滥用 `keepAlive`**——常驻 DOM 与过期视图同时出现，应改用 `cache` 控制时效
- **无节制注册探测型渲染器**——渲染器选择链按注册顺序逐个 `test()`，探测函数应轻量、尽早返回
- **在 `afterRender` 做重活**——渲染后钩子并行执行但位于关键路径末端，重计算建议移出导航流程
