# x-slot 插槽

## 概述

`x-slot` 让组件**预留若干可替换位置（插槽）**，使用者向其中填入自己的内容——组件模板先声明插槽与默认内容，使用处再按名投影覆盖。

- **组件作者**（`x-define` 内）：给需要被替换的元素标上 `x-slot`，插槽内先写一份**默认内容**；
- **组件使用者**（`x-component` 内）：把想放入的内容按名填入——填了就替换，没填就显示默认内容。

```html
<!-- 组件作者：声明两个插槽 + 一段固定页脚 -->
<div x-define="card">
  <header x-slot:header>默认标题</header>
  <div x-slot>默认正文</div>
  <footer>固定页脚（没有 x-slot 标记，永远不会被替换）</footer>
</div>

<!-- 使用者：向插槽填入内容 -->
<div x-component:card>
  <template x-slot:header><h1>自定义标题</h1></template>
  <p>自定义正文（裸子节点 = 默认插槽）</p>
</div>
```

插槽在组件模板里可位于**任意深度**；未提供内容的插槽显示组件内写好的默认内容（fallback）。`x-dialog` 等弹窗**用同一套插槽语法**，但内容归属须显式声明（见[x-slots](./x-slots.md)）——按钮上的裸子节点不会被自动收集。

插槽名通常写死在属性名里；要让**出口数量与名字由数据决定**（如 tabs：每个标签一个出口，新建标签即新建出口），用带值的裸 `x-slot` 声明动态出口、用只读注册表 `$slots` 查看调用方给了哪些名字，见[动态插槽](#动态插槽)。

## 快速入门

组件 `card` 声明了两个插槽（标题 / 正文）和一段固定页脚。对比下面两次使用：

1. **不提供内容**——两个插槽显示组件内写好的默认值，固定页脚照常；
2. **提供内容**——命名插槽用 `<template x-slot:header>` 填入，正文直接写裸子节点，固定页脚不受影响。

**看什么**：第一张卡片全是默认文案；第二张卡片标题换成了大标题、正文带按钮；两者的页脚始终一样。

对应代码如下（对照上方 demo 中的两个面板）：

```html
<!-- 组件：两个插槽 + 固定页脚 -->
<div x-define="card">
  <header x-slot:header>默认头 · {{title}}</header>
  <div x-slot>默认正文</div>
  <footer>© 组件固定页脚</footer>
</div>

<!-- 用法一：不提供内容 → 全是默认值 -->
<div x-component:card></div>

<!-- 用法二：提供内容 → 按名替换 -->
<div x-component:card>
  <template x-slot:header><h3>自定义标题</h3></template>
  <p>这段文字填入默认插槽……</p>
  <button>操作按钮</button>
</div>
```

## 指南

### 指令值

`x-slot` 没有可用的选项和修饰符——全部语义由**指令值（插槽名 / 出口名表达式 / 形参）**承载：

| 形态                                | 用在哪          | 说明                                                                          |
| ----------------------------------- | --------------- | ----------------------------------------------------------------------------- |
| `x-slot`                            | 组件内          | 默认插槽                                                                      |
| `x-slot:<名称>`                     | 组件内 / 使用处 | 按名字对应插槽                                                                |
| `x-slot="<{ 名表达式 }>"`           | 组件内          | **动态出口名**：值求值为字符串即出口名（见[动态插槽](#动态插槽)）             |
| `x-slot="<{ name: 名, params: 值 }>"` | 组件内        | 动态出口名 + 形参取值一并给出（对象形态，见[动态插槽](#动态插槽)）            |
| `x-slot="<{ a, b }>"`               | 使用处          | 向默认插槽传出数据（须写标记，裸子节点不行）                                  |
| `x-slot:<名称>="<{ a, b }>"`        | 使用处          | 命名插槽 + 接收数据                                                           |
| `x-slot:<名称>="<{ 字段: 值 }>"`    | 组件内          | 作用域插槽：要传出的数据                                                      |
| `x-slots="<覆盖物组件名>"`          | 覆盖物宿主子级  | 内容归属容器（仅多消费者必须写，见[x-slots](./x-slots.md)） |

冒号后的段恒为**插槽名**；`=` 后的值按两侧分工——**使用处**（裸 `x-slot="<{ a, b }>"`）是向默认插槽传出的形参，**组件内**带冒号时是要传出的数据（`<{ 字段: 值 }>`，见[作用域插槽](#作用域插槽)）、**不带冒号**时是动态出口名（值求值为字符串即出口名，见[动态插槽](#动态插槽)）。归属容器是独立属性 `x-slots`（值 = 覆盖物组件名），不要与 `x-slot:名` 混淆。

### 定义插槽

在 `x-define` 的组件模板里，给希望被替换的元素写上 `x-slot`：

<demo html="slot/basic.html"/>

| 写法                                | 含义                                                       |
| ----------------------------------- | ---------------------------------------------------------- |
| `<div x-slot>…</div>`               | **默认插槽**（不带名字），元素内容是未提供内容时的默认样子 |
| `<header x-slot:header>…</header>`  | **命名插槽**（`header` 是插槽名），使用者按这个名字填入    |
| `<footer>…</footer>`（没写 x-slot） | **固定内容**，使用者无法替换                               |

要点：

- 带 `x-slot` 的元素**标签会保留**（不会被拆掉）——插槽在哪，DOM 就在哪，便于编写 CSS；
- 插槽可放在模板**任意深度**，嵌套若干层均可；
- 插槽内的内容 = 默认值（未提供内容时原样显示，其中的 `{{}}` 在**组件自身状态**里求值）；
- 插槽清单由编译期**自动扫描**得出，无需也不能额外配置；
- 写在 `x-define` **根元素上无效**（不收集）；写在组件外的 `x-slot` 永远收不到内容，只会作为普通属性渲染。

同名插槽写了多个？只认第一个，后面的会被剥除并提示警告。

### 提供插槽内容

**组件路径**（`x-component:名称`）——在宿主的**直接子级**写入内容：

| 写法                                   | 效果                                                                |
| -------------------------------------- | ------------------------------------------------------------------- |
| 直接写子节点（`<p>正文</p>`）          | 填入**默认插槽**（多个裸子节点合并为一份）                          |
| `<template x-slot:header>…</template>` | 填入名为 `header` 的插槽；`<template>` 自身不渲染，其子节点直接展开 |
| `<div x-slot:header>…</div>`           | 也填入 `header` 插槽，但该 `<div>` 会保留为包裹层                   |

注意：

- 裸子节点（未写 x-slot）会**合并为一份**默认内容（仅组件路径；覆盖物路径裸子节点不参与，见下）；
- 仅**直接子级**参与识别——嵌套更深一层的 `x-slot:xxx` 会被忽略（警告 + 剥除标记属性，元素按普通内容处理）；
- 收集时是**克隆**，不会改动原模板。

**覆盖物路径**（`x-dialog` 等）——同一套 `x-slot:*` 标记语法，但**裸子节点永不参与收集**（按钮标签只属于按钮）。单个 `x-dialog` 时标记可直写宿主子级，多个共用同一宿主时须用 `x-slots="组件名"` 容器分家，详见[x-slots](./x-slots.md)。

**看什么**（demo 中的布局组件有头 / 体 / 脚三个插槽，外加一段固定侧栏）：

1. **第一个面板**——`header`、`footer` 各用 `<template>` 按名填入，中间两个裸子节点（`<p>` 与 `<span>`）合并后填入默认插槽；右侧灰字是固定内容，不受影响；
2. **第二个面板**——`<b x-slot:header>` 写在 `<div>` 内部（不是直接子级），该标记被忽略，整块黄色区域按普通内容进入默认插槽；直接子级的 `header` 模板照常生效。

**试试看**：把第二个面板中 `<b>` 上的 `x-slot:header` 挪到与 `<div class="wrap">` 同级（成为直接子级），再打开控制台查看警告是否消失。

### 内容校验

内容与插槽不匹配时的处理规则（默认警告 + 丢弃、不会静默出错；[动态插槽](#动态插槽)带来的两处例外已标注）：

| 情况                                     | 结果                                                                       |
| ---------------------------------------- | -------------------------------------------------------------------------- |
| 填入的名字没有任何出口消费               | 组件路径：**静默闲置**（进 `$slots`，不渲染也不警告）；覆盖物 / 继承路径：警告并丢弃 |
| 同一个插槽填了两次                       | 只认第一次，后面的丢弃                                                     |
| 插槽标记写在嵌套若干层的子级上           | 忽略（仅认直接子级），按普通内容处理                                       |
| 默认插槽既写了 `x-slot` 标记又有裸子节点 | 二选一，混写会警告                                                         |
| 形参写法不正确（含默认值、改名等）       | 按无形参处理，仅认最简 `{ a, b }`                                          |
| 动态出口名求值失败                       | 警告 + 按无内容处理（出口保留、渲染 fallback）                             |

### 作用域插槽

有时内容需要使用组件内部的数据（例如列表组件把当前行交给外部渲染），这叫**作用域插槽**，两侧各写一半：

```html
<!-- 组件侧：插槽上声明「要传出的数据」 -->
<div x-define="list">
  <div x-slot:row="{ item: rows[0], index: 0 }">默认行</div>
</div>

<!-- 使用侧：内容上声明「要接收哪些字段」 -->
<div x-component:list>
  <template x-slot:row="{ item, index }">{{ index }}. {{ item }}</template>
</div>
```

- 组件侧计算数据并传出；使用侧解构后即可使用；
- 组件数据变化时内容会**自动刷新**（不是一次性快照）；
- 仅当内容侧声明了形参，组件侧才会计算——不声明则完全不求值；
- 形参会**遮蔽**使用侧同名变量（就近查找优先）——需要外部值请换名；
- 仅支持最简单的 `{ a, b }`，不能改名、不能写默认值。

**看什么**（demo 中的列表组件把 `rows[0]` 传给外部，外部用蓝底徽章 + 粗体自定义渲染）：

1. **中间面板**——内容侧解构了 `{ item, index }`，显示为 `#0 甲`；
2. **点绿色按钮**——组件内部把 `rows[0]` 改为 `"乙"`，中间面板的 `甲` **原地变为 `乙`**（传出的是响应式引用，不是快照）；
3. **最下面面板**——不提供任何内容，显示插槽内的灰色 fallback 文案。

**试试看**：点完按钮后注意观察——只有中间面板变化，下面的 fallback 面板保持不变（它没有订阅形参）。

### 动态插槽

静态出口的名字写死在属性名里，出口集合在编译期就固定了。要让**出口数量与名字由数据决定**——拿最常见的 tabs 组件来说：标签栏随数据增减，每个标签渲染一个出口，面板内容由调用方按名填入。组件侧用**带值的裸 `x-slot`** 声明动态出口，配合组件实例域的只读注册表 `$slots` 查看调用方给了哪些名字：

```html
<!-- 组件：标签栏与出口都由数据决定 -->
<div x-define="tabs">
  <div class="tab-row" x-for="key of tabs">
    <button x-on:click="active = key">{{ key }}</button>
  </div>
  <!-- 每个标签一个出口：对象形态 name 承出口名、params 传出下标 -->
  <div class="panes" x-for="key, i of tabs">
    <div x-show="key === active" x-slot="{ name: key, params: { index: i } }">
      默认面板 · {{ key }}
    </div>
  </div>
</div>

<!-- 使用者：名字恒写在属性名里，可为「将来的标签」预置内容 -->
<div x-component:tabs>
  <template x-slot:home="{ index }">首页 · 第 {{ index + 1 }} 个标签页</template>
  <template x-slot:profile>个人资料</template>
  <template x-slot:tab-4>为新建 tab 预置的内容</template>
</div>
```

要点：

- **值是表达式，不是名字字面量**：字符串形态 `x-slot="key"` 求值 `key` 得到字符串即出口名（只承名）；对象形态 `x-slot="{ name, params }"` 里 `name` 承出口名、`params` 传出[作用域插槽](#作用域插槽)的形参取值（承名 + 传数据）。要写静态名一律用 `x-slot:header`——`x-slot="header"` 是在找名为 `header` 的变量，求不到就降级；
- **名只求值一次、静态绑定**：出口创建时求值一次后固定，**不响应式**——改名 / 新增出口靠 `x-for` 让子树重建（上例的出口挂在 `x-for` 项里，新建标签即新建出口）；`params` 走 watch 通道，**保持响应式**；
- **`$slots` 是只读注册表**：组件实例域的框架保留键，值为「本实例收到的内容段」的名 → `{ name }` **冻结快照**（`default` 段在内，无内容时是空对象）。`Object.keys($slots)` 即「调用方提供了哪些名字」；给它赋值只得到一次警告，不会生效；
- **同一段内容多处消费各自克隆**：`x-for` 迭代出 N 个动态出口取到同一段内容时，独立编译 N 份（各自 scope / watcher / DOM），互不影响；
- **内容名恒静态**：调用侧的名字只能写在属性名里（属性名无法承载表达式）——调用方静态决定「有哪些名字」，组件动态决定「渲染哪些、渲染到哪」，所以内容可以为将来的标签**预置**，却不能在运行时临时造一个名字；
- **未被消费的内容段静默闲置**：组件路径按全量收集，名字没被任何出口取走也不警告、不渲染（只躺在 `$slots` 里）；
- **无效名降级**：值求值为 `null` / 数字 / 空串 / 缺 `name` 的对象时，警告 + 按无内容处理（渲染 fallback）；
- **覆盖物路径与继承覆盖不放行**：`x-dialog` 的内容仍按静态出口清单校验（动态名的内容警告丢弃），`x-define:inherit` 覆盖同样不支持动态出口——动态出口主要服务组件路径。

**看什么**（demo 是一个 tabs 组件，标签栏与出口都来自组件数据 `tabs`）：

1. **上面面板**——三个标签 `home` / `profile` / `about`：前两个命中调用方内容（标签上有**蓝点**），`about` 没有内容 → 显示默认面板；顶行 `$slots` 清单里还有个 `tab-4`——内容已就位，但**此刻还没有这个标签**（没有出口取它，静默闲置）；
2. **点「＋ 新建 tab」**——新建出 `tab-4` 标签与它的出口，**立刻命中预置内容**（下标形参 `index` 照常注入）；顶行清单纹丝不动（内容名恒静态，变的只是出口集合）；
3. **再点一次**——`tab-5` 只能显示默认面板：调用方没给这个名字提供内容，组件路径不警告；
4. **下面的对照面板**——不提供任何内容：`$slots` 是空对象，蓝点全灭，所有标签都走默认面板。

**试试看**：把 `<template x-slot:home>` 改名成 `x-slot:home2`——`home` 标签立刻退回默认面板（组件路径名字对不上**不警告**，只静默闲置），顶行清单也同步变成 `home2、profile、tab-4`。

### 叠加默认内容（x-super）

提供内容默认是**整体替换**插槽的默认内容。想在自定义内容里**引用**被覆盖的默认内容（前缀增强、包裹、交错排版），在内容里写 `<x-super></x-super>` 标记——它会把**本段覆盖掉的默认内容**原位展开进标记元素内部：

```html
<div x-component:card>
  <template x-slot:header>
    <h3>自定义标题</h3>
    <x-super></x-super><!-- 展开 header 插槽的默认内容（组件状态求值） -->
  </template>
  <p>前缀<x-super></x-super>后缀</p>
  <!-- 默认插槽同理，可交错 -->
</div>
```

标记恒为自引用（只展开**本段覆盖的那一个插槽**的默认内容），同一段可写多次、各自独立展开；展开部分在**组件状态**求值，自定义内容在**使用处状态**求值，两段状态互不混淆。语义要点、边界规则、包裹层样式与完整示例见 [x-super](./x-super.md)。

### 求值作用域

填入的插槽内容在**使用处的状态**里求值——可读取页面上的 `x-data`、全局 state，**不受组件内部封闭影响**。未提供内容时显示的默认内容，则在**组件自身状态**里求值。

```html
<!-- 这里的 msg 是页面状态，不是组件内部状态 -->
<div x-data="{ msg: '你好' }">
  <div x-component:card>
    <p>{{ msg }}</p>
    <!-- 读取调用方的 msg -->
  </div>
</div>
```

**看什么**（demo 中页面 `x-data` 有 `label = "外层"`，全局有 `globalMsg = "全局"`，组件自身有 `title = "组件标题"`）：

1. **中间面板（有内容）**——蓝色粗体显示 `外层 · 全局`：这是填入的 `{{label}}`、`{{globalMsg}}`，读取的是**页面和全局**，组件封闭也无法拦截；
2. **下面面板（无内容）**——灰色 fallback 显示 `fallback · 组件标题`：这是组件内的默认文案，`{{title}}` 读取的是**组件自身**状态；
3. 两块绿色固定区始终显示 `组件标题`——它不在插槽内，始终处于组件语境。

**对照着看**：同一段代码里的 `{{label}}` 与 `{{title}}`，一个在外层、一个在组件内，求值位置完全不同。

<demo html="slot/caller.html"/>

嵌套组件时内容不会串台：内层组件的插槽只认自己收到的那份内容，找不到就显示自身的默认值，不会向外层查找。

### 覆盖物内容归属（x-slots）

`x-dialog` 等覆盖物用**同一套** `x-slot` / `x-slot:名` 插槽语法，但宿主侧的规则与组件路径不同：

> **覆盖物宿主的裸子节点（按钮标签等）永不参与收集**——内容必须显式声明。单个 `x-dialog` 时标记可直写宿主子级，多个共用同一宿主时须各套 `x-slots="组件名"` 容器分家——`x-slot:名` 的冒号段恒为**出口 / 内容名**，归属只写在 `x-slots`（等号）上。

```html
<!-- 单消费者：标记直写宿主子级，按钮标签照常 -->
<button x-dialog:confirm="ui.open">
  <div x-slot>要确认吗？</div>
  打开
</button>

<!-- 多消费者：各套归属容器 -->
<button x-dialog:save="ui.save" x-dialog:cancel="ui.cancel">
  <template x-slots="save">保存当前草稿？</template>
  <template x-slots="cancel">放弃所有修改？</template>
  提交
</button>
```

### 常见警告

| 控制台提示                                | 处理方式                                                                         |
| ----------------------------------------- | -------------------------------------------------------------------------------- |
| `内容 "xxx" 无对应出口`                   | 覆盖物 / 继承路径未命中静态出口清单——补出口或删内容（组件路径已改为静默闲置）     |
| `插槽内容 "xxx" 重复`                     | 同名内容写了多次——只保留一处                                                     |
| `嵌套 x-slot 标记已忽略`                  | 插槽标记位置过深——挪到直接子级                                                   |
| `出口 "xxx" 重复声明`                     | 组件内同名插槽写了多处——删除一处                                                 |
| `形参须为简单解构形`                      | 形参写法过复杂——改为 `{ a, b }`                                                  |
| `动态出口名无效（…）`                     | 裸 `x-slot` 的值求值结果不是非空字符串 / `{ name, params }` 对象——检查表达式里的变量在组件作用域是否可见 |
| `动态出口 "xxx" 不可消费活体内容段`       | 动态出口撞上 shell 活体段（live 段只能被静态出口直挂）——该位置改写静态出口        |
| `$slots 是只读保留键`                     | 别给 `$slots` 赋值——它只读，另建组件 data 存放自己的状态                          |

`x-slots` 归属容器与 `x-super` 标记的警告清单见 [x-slots](./x-slots.md) 与 [x-super](./x-super.md)；覆盖物路径的警告会带 `x-dialog:名称: ` 前缀。

## 注意事项

- **内容标记须写在直接子级**：仅宿主的直接子级会被识别，更深一层的标记会警告并按普通内容处理；
- **覆盖物宿主的裸子节点不收集**：`x-dialog` 的按钮标签等永远留在宿主；内容要么显式写标记（单消费者），要么套 `x-slots="组件名"` 容器（多消费者），见[x-slots](./x-slots.md)；
- **`x-slots` 与 `x-slot` 是两个东西**：`x-slot:名` 的冒号段恒为**出口名**，归属只写在 `x-slots="组件名"` 上；
- **标签不会被拆掉**：插槽标记的元素保留为包裹层（拆掉后默认内容没有宿主、CSS 也不便编写）；
- **名字不匹配不会插错位置**：内容没有出口消费时——组件路径**静默闲置**（进 `$slots`，不渲染也不警告），覆盖物 / 继承路径警告丢弃，任何情况下都不会插入到错误位置；
- **裸 `x-slot` 的值是动态名通道**：值是**表达式**不是名字字面量（`x-slot="header"` 是在求变量 `header`）——静态名一律写 `x-slot:header`，见[动态插槽](#动态插槽)；
- **动态出口名只求值一次**：创建时求值后固定、**不响应式**，改名 / 新增出口靠 `x-for` 重建子树；只有对象形态里的 `params` 走 watch 保持响应式；
- **`$slots` 只读**：冻结快照，赋值被忽略并警告；它只在组件实例作用域可见，组件外读到 `undefined`；
- **形参会遮蔽同名变量**：内容侧声明形参后，使用侧同名变量被遮蔽——需要外部值请换名或不声明形参；
- **形参不是 JSON**：仅支持最简写法 `{ a, b }`，不能改名、不能有默认值；
- **插槽自动识别，无配置项**：不要尝试 `slots: ['header']` 之类写法（不存在）；
- **`x-super` 只在插槽内容里生效**：标记展开的是本段覆盖的默认内容，写在别处只得到警告与空元素；必须双标签 `<x-super></x-super>`（自闭合形式会吞兄弟节点）；嵌套组件内容里的标记归**内层**插槽解析，不会穿透——语义要点与边界规则见 [x-super](./x-super.md)；
- **勿与 x-isolate 混淆**：见页首提示——一个是隔离区域，一个是可替换位置；
- **x-tree 的节点模板不走插槽**：两者是独立机制；
- **继续阅读**：组件声明、数据边界、生命周期见 [x-define](./x-define.md)、[x-component](./x-component.md) 与[组件](../component/)；弹窗用法见 [x-dialog](./x-dialog.md)。
